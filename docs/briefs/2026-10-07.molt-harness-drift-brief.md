# Brief: bring Firstmate's instruction prose and worker transport in line with what Claude Code and Pi now do natively

Tracker: none yet (file with `/loop-track` once the captain agrees the scope).
Date: 2026-10-07.
Stage: molt audit output, consumed by /loop-plan.
Source of record: the molt findings report at `~/.config/jrit/molt/runs/2026-10-07.firstmate-agents-md.md` and its companions in the same folder.

## Outcome

Firstmate's always-loaded contract stops paying for prose the harness already enforces, keeps every rule the harness will not enforce, and the one subsystem that still emulates a missing harness capability, the worker transport, gets a native path on Claude.
The fleet keeps running on two primary harnesses, Claude Code and Pi, and every change is judged against both.
Presupposition check: the ask was "what could be slimmed down or gotten rid of".
The audit found that the scripts and skills are not the weight; the weight is prose paid on every session and a transport that reads screens instead of return values.
Verdict: slim the prose, leave the code surface alone, and modernize the transport.

## Approach

### Chosen: three steps in dependency order, each with its own check

Step 1, prose and hygiene, both harnesses.
Apply the two patches when the fleet is idle, because a live session re-reads AGENTS.md after compaction.
Then run the decision-hold removal as a crewmate task from its brief.
The prose patch removes four duplications (hard rule 4, idle-by-default, the away-mode trigger, local-only), two choreography blocks (the persisted-output line and the eleven-line internal-term table), moves the nine quota-array intake rules into the skill that already pointed back at them, rewrites the false "only three surfaces are loaded" premise, and reduces two flag lines to their outcome.
Check: `bash bin/fm-doc-audience-check.sh` and the six owning tests, all of which passed in a scratch clone on 2026-10-07.

Step 2, Pi skill discovery, Pi first, then both.
Add `.pi/skills -> ../.agents/skills`.
Start Pi in the home and confirm the available-skills block names the agent-only skills.
Only then delete the seven lines whose whole content is "Load <skill> when <its description>" (AGENTS.md lines 62, 85, 242-253, 304-307 at the pre-patch numbering) and section 13 (lines 404-408), 23 lines in all.
Keep the pointers that add a condition the description lacks (lines 132, 137, 283, 286, 300-302).
Check: the Pi listing observed, then `tests/fm-task-delivery.test.sh` and `tests/fm-session-start.test.sh`, which pin the role-contract lines and the AGENTS.md hash handling.

Step 3, native worker transport, Claude only.
Prerequisite, from the backlog item composer-label-steer-block (2026-10-05): fix the pane path first, or the bakeoff proves nothing because arm A loses by default on the very workflow used as the test task.
Two defects, both reproduced end to end before any fix: composer-lib reads the input line whose border carries the label "Firstmate operational input" as unknown, so doorbells report "did not reach" and relaunch refuses; and fm-control does not answer Claude Code's "Background work is running" exit dialog, so a worker with a background shell cannot be exited or relaunched.
The fix stays inside bin/fm-composer-lib.sh and bin/fm-control-lib.sh, with a portable regression for each and a live guard in the live-harness-optin family, per the coding guidelines' harness-dependent-check rule.
Run a bakeoff only after that fix lands, and before any backend code exists.
Arm A is the current path: spawn into a Herdr pane, steer with `fm-send` doorbells, classify the composer from the screen.
Arm B is a Claude worker started as a background session, steered through the message channel, with delivery status written into the same durable inbox record.
Task: one jrit chain stage on a registered project, the same brief for every run.
Checklist, binary, written before run one: steer acknowledged within the watcher cadence, relaunch succeeds on first attempt, no composer verdict of unknown, no captain intervention needed, worker reaches its declared stop.
Keep rule, fixed before run one: build the backend only if arm B scores strictly higher on at least two checklist items across three runs and never lower on any.
If the keep rule holds, the backend owns only transport and status; briefs, teardown, merge guards, and the durable queue stay exactly as they are.

### Considered and declined

- Deleting unused script families in the fork (remote mates, Relay, voice, mail, three backends, away daemon, quota dispatch, other harnesses, labs): zero runtime cost because scripts never enter model context, and every family is upstream code that still changes, so deletion buys merge conflicts and nothing else.
- Deleting skills with unreachable triggers (orca, codexapp, fmx-respond, quota-array-dispatch, secondmate-provisioning): their always-loaded cost is their descriptions only, about 2,900 tokens for all 29, and the same merge argument applies.
- Deleting hard rule 5 and the final-message bullets: native on Claude, absent on Pi; a Pi primary has no other source for them, and a Pi-only emitted block is a mechanism not worth owning for seven lines.
- Sending findings upstream: the captain ruled fork-only.
- Rewriting the pane transport for Pi: Pi already has the native supervision-branch extension and is the harness that behaves in `data/learnings.md`.
