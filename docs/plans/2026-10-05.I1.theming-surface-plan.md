# Theming Surface Implementation Plan

> For executors: tasks use checkbox syntax; execute in dependency order; a task is done when its acceptance check passes. No specific tooling, harness, or skills are assumed.

**Goal:** Give each Firstmate home a selectable look and no-op reply for the fleet board and the session digest, proven by two shipped themes, while a home that selects nothing sees exactly today's board and reply.

**Approach:** One small resolver, `bin/fm-theme.sh`, reads the gitignored `config/theme`, finds the named theme in the home's themes folder first and the shipped themes folder second, refuses unsafe stylesheets, and inlines local fonts into one self-contained stylesheet.
The board build injects that stylesheet into a second template slot and sets the page root's theme, layout, and mode attributes, while the template gains geometry-only layout rules, mode-to-color-scheme rules, three hidden frame hooks, and in-page layout and mode switches.
The session digest prints one theme line naming the theme, its no-op reply, and the resolved stylesheet, and the two AGENTS.md no-op-reply lines defer to that line.

**Tech stack:** Bash (stock macOS 3.2 compatible) with perl core modules and jq for `bin/` scripts; HTML, CSS (`light-dark()`, `color-scheme`), and vanilla JavaScript in the board template; Node for the existing render harness; Python 3 and headless Google Chrome for proofs kept outside the repo; git 2.38 or newer for `merge-tree --write-tree`.

**Source brief:** docs/briefs/2026-10-05.I1.theming-surface-brief.md (tracker jroethel/firstmate#1).

## Decisions

Decided before planning (recorded, not reopened):

- D1: The per-home selection is the local, gitignored `$FM_HOME/config/theme` with optional `theme=<name>`, `layout=full|compact`, and `mode=light|dark|auto` lines; no file means today's board exactly; docs/configuration.md documents it beside the Calm preference; `data/captain.md` never holds it.
  Reason: it is the house pattern for a small per-home setting and keeps the captain file lean.
- D2: Shipped themes live in `.agents/skills/bearings/assets/themes/<name>/` and home themes in `$FM_HOME/config/themes/<name>/`; lookup is by name, home first, shipped second; a missing name stops the build naming the name and both folders searched, and nothing is written.
  Reason: a home can override or add a theme without editing tracked files.
- D3: A theme folder holds one stylesheet `theme.css` (type pairing plus colors for both modes, selected through the root's mode attribute), optional local font files, and an optional voice line; themes override the template's existing custom properties and may override component rules in their own stylesheet; there is no semantic-token refactor of the template.
  Reason: the slot stays small; the refactor is parked in the brief.
  No template raw-token use is moved to a semantic token by this plan, because a theme can override the component rule itself; an executor who finds a case a theme genuinely cannot reach names it in the commit message and the PR body.
- D4: No theme, shipped or home, may fetch anything: no remote `url()` and no `@import`; fonts are local files after a redistribution-license check, committed with their license, and inlined by the build as `data:` URLs.
  A home theme is also refused for any `<`; shipped themes are exempt from that markup check only; Task 3 states the exact detection rule.
  Reason: the board's script routes keyed answers back into Firstmate, so its page must not be escapable or phone home.
- D5: The template gains three empty decorative hooks and one rule hiding them: `<div class="bb-frame-elbow" aria-hidden="true"></div>` as the first child of `<body>`, `<div class="bb-frame-rail" aria-hidden="true"></div>` directly after `</header>`, `<div class="bb-frame-cap" aria-hidden="true"></div>` directly after `</main>`, and `.bb-frame-elbow, .bb-frame-rail, .bb-frame-cap { display: none; }`; only theme stylesheets show and style them; the full layout moves the count strip into a left column by grid geometry.
  Reason: a real frame needs real boxes, and hidden boxes change nothing for a home with no theme.
- D6: Layout rules live in the template and own geometry only; with no `config/theme` the root carries no layout or mode attribute; `full` is the big-screen full-bleed layout and `compact` the laptop layout; `mode=auto` follows the system live; in-page layout and mode switches start from the home default, are session-only, and appear only when `config/theme` exists; switching the theme itself is a setting change plus a rebuild.
  Reason: layout and colors stay independent axes, and one in-page theme switch would carry every theme's CSS and fonts in every board.
- D7: LCARS names `Captain, all systems nominal.`; Restrained names no reply; AGENTS.md changes exactly two lines (the no-op reply lines in section 9) so the reply is `Captain, shipshape.` unless the digest's theme line names another.
  The Pi regression example in docs/supervision-protocols/pi.md is not edited.
  Reason: that line is marked "keep verbatim", and it describes the default reply, which stays correct for every home without a theme.
- D8: `bin/fm-session-start.sh` prints one theme line only when a theme is named, carrying the name, the no-op reply, and the path of a self-contained resolved stylesheet; one resolver serves the board build and the digest.
  Reason: a home with no theme pays nothing, and there is one owner of theme resolution.
- D9: LCARS ships as-is apart from font localization and one reworded comment (its line 2 says "@import", which the fetch rule refuses even inside a comment), in its own task and its own commit confined to its folder; no theme name, font name, or hex value appears outside the two theme folders and tests.
  Reason: the later upstream stage removes LCARS with one `git rm -r` and upstream sees a neutral slot.
- D10: Fork sync is two recorded git commands plus a proof script on throwaway repos; no `bin/` command; recording the commands in the home's `data/learnings.md` is a human checkpoint.
  Reason: a `bin/` command would enter lint, coverage, and doc-audit sets the upstream branch must excise.
- D11: Proof renders all eight shipped combinations (2 themes by 2 layouts by 2 modes) in headless Chrome at 1280 and 390 pixels wide (plus 900 and 901 for overflow at the layout breakpoint, without screenshots); the eight 1280 screenshots go in the PR body; proof output stays under /home/jjrdar/_no1/data/firstmate-i1-chain/; Restrained contrast is recomputed from the shipped stylesheet with the scout's contrast tool.
  Reason: CI has no browser, and screenshots are evidence, not repo content.
- D12: Out of scope: renaming internal vocabulary, changing `/updatefirstmate`, themes for worker-authored project pages, any action in kunchenguid/firstmate, and every parked item in the brief.
  Reason: the brief's out-of-scope list and parking lot.

Added during planning (each verified against the repo or the network on 2026-10-05 unless marked):

- D13: Theme colors use `light-dark(<light>, <dark>)`, and the template maps the root's mode attribute to `color-scheme` (`light`, `dark`, or `light dark` for auto).
  Reason: one declaration per color, and auto follows the system live with no script.
- D14: The build sets `data-theme` (only when a theme is named), `data-layout`, and `data-mode` on the root whenever `config/theme` exists, in that order; the template's `color-scheme` rules key on `[data-theme]`, and the mode switch shows only when `data-theme` is present.
  Reason: a layout-only selection keeps the default look, which has one mode, so dark form controls never land on the light default page.
- D15: Defaults inside an existing `config/theme`: `layout=compact`, `mode=auto`, and reply `Captain, shipshape.`.
  Reason: compact is closest to today's 1180px page, and auto is the brief's mode default.
- D16: When a theme is named, the build drops the template's `@import` font line from the built page.
  Reason: the template's Google Fonts import would otherwise make a themed board fetch remote CSS.
- D17: The build reads the resolved stylesheet from a temporary file inside perl, never through an environment variable or argument.
  Reason: Linux caps one environment string at 128 KiB, and Restrained's inlined fonts are about 111 KB of base64.
- D18: The voice file is `noop-reply` and the font license file is `fonts/LICENSE`, with no `.txt` or `.md` extension.
  Reason: `bin/fm-doc-audience-check.sh` treats every tracked `*.md` and `*.txt` file as prose that must be classified.
- D19: A voice line must be exactly one line of at most 120 characters that starts with `Captain, ` and otherwise uses only letters, digits, spaces, and `, . ! ? ' ( ) -`, so it can never carry a `;` (the digest line's field separator), a backtick, or a control character.
  Reason: AGENTS.md requires addressing the captain in every chat message, and the address term itself is parked.
- D20: Restrained ships IBM's official, unmodified Latin1 split woff2 files (`@ibm/plex-sans@1.1.0`, `@ibm/plex-sans-condensed@2.0.0`, `@ibm/plex-mono@2.5.0`); LCARS ships Google's latin-range Antonio woff2.
  Reason: the Plex license reserves the font name "Plex", so a self-made subset would be a Modified Version; Antonio's OFL (google/fonts `ofl/antonio/OFL.txt`) declares no reserved name.
- D21: Restrained declares its palette as 23 `--rs-<role>: light-dark(#light, #dark)` custom properties using the scout's role names, then maps template properties onto them.
  Reason: the scout's contrast tool can then read the shipped stylesheet directly.
- D22: Layout rules also define frame geometry custom properties (`--bb-frame-side`, `--bb-frame-bar`, `--bb-frame-radius`) that themes use when they show the hooks.
  Reason: frame size belongs to the layout axis, so any theme frame works in both layouts.
- D23: The digest's theme line prints in a small THEME section directly after the read-once contract, inside the existing read-once stage, and a lock-refused (read-only) session prints it without rewriting the fleet-page stylesheet.
  Reason: the digest is truncated from the tail, so an early line survives truncation, and a read-only session must not write fleet files; keeping it inside an existing stage leaves the stage list behind the truncation banner unchanged.
- D24: The fleet-page stylesheet is written to `$FM_HOME/.lavish/fleet-theme.css`, beside the board, in the already gitignored `.lavish/`.
  Reason: Lavish pages are built there, and the path is stable per home.
- D25: Tests for shipped themes loop over every folder in the shipped themes directory and never name a theme.
  Reason: the LCARS commit then touches only its own folder, which keeps D9's removal a one-line operation.
- D26: `bin/fm-test-run.sh` gains one changed-file map arm for `.agents/skills/bearings/assets/*` and `tests/assets/board-render-harness.mjs`.
  Reason: today `--changed` stops with "no changed-test mapping" for `tests/assets/*` and for any asset path no test names, which would fail brief criterion 4.
- D27: docs/documentation-audiences.json classifies the branch's loop paperwork (docs/loop, docs/briefs, docs/plans files).
  Reason: `bin/fm-doc-audience-check.sh` already fails on this branch, reporting those files unclassified.
- D28: The two fork-sync command lines fetch both mains, then refuse when `origin` and `upstream` share a URL, do nothing when fork main already contains upstream main, push upstream main directly when fork main has no commits of its own, and otherwise merge with `merge-tree` and `commit-tree` and push the result without force; they never touch the home's checkout or create a worktree.
  Reason: the update command can then report the fast-forward criterion 8 requires, and the `&&` chain means a conflict never pushes an empty ref (an empty source ref would delete fork main).
- D29: The bearings skill gains one trigger clause and one sentence pointing a theme, layout, or mode request at `config/theme` plus a rebuild.
  Reason: brief "Done looks like" item 1 needs Firstmate to know where a chat request lands.
- D30: Proof builds use a `lavish-axi` stub that always fails.
  Reason: the build publishes the board file before opening a Lavish session, so the stub stops it there and no session, binding, or listener is created.
- D31: Today's board shows two controls it means to hide (the empty Captain's Call navigator and the dispatch bar), because their `display: flex` rules override the `hidden` attribute; Task 13 fixes it with one global `[hidden] { display: none !important; }` rule, as its own commit.
  Reason: the captain approved the fix for this PR (plan round 3), and a separate commit lets the upstream branch carry it or split it out; the render harness has no CSS, so criterion 1's equivalence is unaffected.
- D32: No Content-Security-Policy is added to the board in v1; it is parked.
  Reason: the page's answers travel through Lavish's `queuePrompt` bridge, whose transport is unverified, and a CSP could silently break answer routing; the resolver's refusal rules are the v1 guard.
- D33: Task 14 checks the brief's two "believed, unchecked" Lavish facts before any template work; if `light-dark()` or live auto fails in the served frame, auto falls back to the pinned mode (the build would resolve `mode=auto` to `dark`), the in-page switches are parked, and the run stops for a plan revision.
  Reason: the brief names that fallback, and Tasks 5 through 7 would build on a false premise otherwise.
- D34: Every theme's folder and `theme.css` must not be symlinks, and `theme.css` plus its referenced fonts must total at most 512 KiB (524288 bytes).
  Reason: a symlink could point the build outside the theme folder, and the cap bounds the board file each rebuild rewrites while leaving about five times Restrained's roughly 90 KB.

- Produces `fm-theme.sh selection`: nothing and exit 0 when `CONFIG/theme` is absent; otherwise exactly these six lines in this order, with defaults `layout=compact`, `mode=auto`, and `reply=Captain, shipshape.`:

```text
theme=<name, or empty when no theme is named>
layout=<full|compact>
mode=<light|dark|auto>
origin=<home|shipped|none>
dir=<absolute theme folder, or empty>
reply=<no-op reply>
```

- Produces `fm-theme.sh css`: the resolved stylesheet on stdout, exit 0; exit 1 with `fm-theme: no theme is selected in <CONFIG>/theme` when none is named, or with `fm-theme: theme "<name>" (<path to theme.css>) refused: <reason>` when a rule below fails.
- Refusal rule, applied to the raw bytes of `theme.css` with no CSS parsing, so comments are not exempt and every token match is ASCII case-insensitive:
  - Markup rule, home themes only: any `<` character is refused; this covers `</style` in any case, `<!--`, and `<script`, and it also refuses media-query range syntax such as `(width < 600px)`, which home themes write as `max-width` instead.
  - Escape rule, every theme: any `\` character is refused, because a CSS escape can spell a refused token (`\75 rl(` is `url(`); a theme writes the literal UTF-8 character instead of an escape.
  - Fetch rule, every theme: any `@import`, `image-set(` (which also covers `-webkit-image-set(`), `image(`, or `src(` is refused.
  - Location rule, every theme: the theme folder and its `theme.css` must not be symlinks, and `theme.css` must be a regular file; a symlink would let a theme name point the build at a file outside its folder.
  - Size rule, every theme: `theme.css` plus every font file it references must total at most 524288 bytes (512 KiB) before encoding; Restrained, the largest shipped theme, totals about 90 KB, so the cap leaves about five times headroom while bounding the board file every rebuild rewrites and the fleet-page stylesheet the digest names.
  - Font rule, every theme: every `url(` must match `url\(\s*(["']?)fonts/([A-Za-z0-9][A-Za-z0-9._-]*\.woff2)\1\s*\)` (perl, case-insensitive), and `fonts/<file>` must be a regular file that is not a symlink inside that theme folder; any other `url(`, including `data:` and remote addresses, is refused.
- Inlining: every allowed font reference, whatever its case, quoting, and inner spacing, becomes exactly `url("data:font/woff2;base64,<unwrapped base64 of the file>")` (perl `MIME::Base64`, encoded with an empty line ending).

- Fallback, from the brief: if `light-dark()` or live auto fails inside the served frame, auto falls back to the pinned mode (the build would resolve `mode=auto` to `dark`) and the in-page switches are parked; the executor then stops the run and reports the result file instead of starting Task 5, because Tasks 5 through 7 need a plan revision under that fallback.

```bash
#!/usr/bin/env bash
# lavish-spike.sh - check, inside Lavish's served frame, that color-scheme plus light-dark() follow
# a root data-mode attribute, that clicking an in-page switch changes that attribute, that auto
# follows the emulated system scheme live, and that a file rewritten at the same path shows on
# reload at the same session address. Writes lavish-spike-result.txt beside itself.
set -uo pipefail
DIR=$(cd "$(dirname "$0")" && pwd)
PAGE="$DIR/spike.html"
RESULT="$DIR/lavish-spike-result.txt"
: > "$RESULT"
core_fails=0
reload_fails=0
record() {  # <name> <pass|fail> <detail>: same-address and rebuilt-file-on-reload are reload checks
  printf 'check %s: %s %s\n' "$1" "$2" "$3" >> "$RESULT"
  if [ "$2" != pass ]; then
    case "$1" in
      same-address|rebuilt-file-on-reload) reload_fails=$((reload_fails + 1)) ;;
      *) core_fails=$((core_fails + 1)) ;;
    esac
  fi
}
write_page() {  # <build-number>
  cat > "$PAGE" <<HTML
<!doctype html>
<html lang="en" data-theme="spike" data-mode="light" data-build="$1">
<head><meta charset="utf-8"><title>spike</title>
<style>
:root[data-theme][data-mode="light"] { color-scheme: light; }
:root[data-theme][data-mode="dark"] { color-scheme: dark; }
:root[data-theme][data-mode="auto"] { color-scheme: light dark; }
#probe { color: light-dark(rgb(1, 2, 3), rgb(250, 251, 252)); }
</style></head>
<body><p id="probe">probe</p>
<button type="button" id="to-dark" onclick="document.documentElement.setAttribute('data-mode', 'dark')">Dark</button>
<button type="button" id="to-auto" onclick="document.documentElement.setAttribute('data-mode', 'auto')">Auto</button>
</body></html>
HTML
}
# Evaluate <js> in the served frame (or the top page when Lavish serves no frame) and print the
# JSON text the page returned.
frame_eval() {  # <js-body returning a JSON-able value>
  local js out
  js="() => { const f = document.querySelector('iframe'); const d = f ? f.contentDocument : document; if (!d) return JSON.stringify({error: 'frame not reachable'}); return JSON.stringify((function (d) { $1 })(d)); }"
  out=$(chrome-devtools-axi eval "$js" 2>/dev/null | sed -n 's/^result: //p' | head -1)
  out=$(printf '%s' "$out" | jq -r 'if type == "string" then . else tojson end' 2>/dev/null)
  case "$out" in \"*) out=$(printf '%s' "$out" | jq -r . 2>/dev/null) ;; esac
  printf '%s' "$out"
}
probe='const r = d.documentElement; return { mode: r.getAttribute("data-mode"), build: r.getAttribute("data-build"), color: getComputedStyle(d.getElementById("probe")).color };'

write_page 1
first=$(lavish-axi "$PAGE" 2>&1)
url=$(printf '%s\n' "$first" | sed -n 's/^[[:space:]]*url:[[:space:]]*"\{0,1\}\([^"]*\)"\{0,1\}[[:space:]]*$/\1/p' | head -1)
if [ -z "$url" ]; then record session fail "lavish-axi printed no url: $first"; else record session pass "$url"; fi
chrome-devtools-axi open "$url" >/dev/null 2>&1
chrome-devtools-axi emulate --color-scheme light >/dev/null 2>&1
sleep 2

v=$(frame_eval "$probe")
if printf '%s' "$v" | jq -e '.mode == "light" and .color == "rgb(1, 2, 3)"' >/dev/null 2>&1; then record light-mode pass "$v"; else record light-mode fail "$v"; fi

v=$(frame_eval 'd.getElementById("to-dark").click(); '"$probe")
if printf '%s' "$v" | jq -e '.mode == "dark" and .color == "rgb(250, 251, 252)"' >/dev/null 2>&1; then record switch-to-dark pass "$v"; else record switch-to-dark fail "$v"; fi

v=$(frame_eval 'd.getElementById("to-auto").click(); '"$probe")
if printf '%s' "$v" | jq -e '.mode == "auto" and .color == "rgb(1, 2, 3)"' >/dev/null 2>&1; then record auto-under-light pass "$v"; else record auto-under-light fail "$v"; fi
chrome-devtools-axi emulate --color-scheme dark >/dev/null 2>&1
sleep 1
v=$(frame_eval "$probe")
if printf '%s' "$v" | jq -e '.mode == "auto" and .color == "rgb(250, 251, 252)"' >/dev/null 2>&1; then record auto-follows-system-live pass "$v"; else record auto-follows-system-live fail "$v"; fi

write_page 2
second=$(lavish-axi "$PAGE" 2>&1)
url2=$(printf '%s\n' "$second" | sed -n 's/^[[:space:]]*url:[[:space:]]*"\{0,1\}\([^"]*\)"\{0,1\}[[:space:]]*$/\1/p' | head -1)
if [ "$url2" = "$url" ]; then record same-address pass "$url2"; else record same-address fail "first $url, then $url2"; fi
chrome-devtools-axi open "$url" >/dev/null 2>&1
sleep 2
v=$(frame_eval "$probe")
if printf '%s' "$v" | jq -e '.build == "2"' >/dev/null 2>&1; then record rebuilt-file-on-reload pass "$v"; else record rebuilt-file-on-reload fail "$v"; fi

lavish-axi end "$PAGE" >/dev/null 2>&1
if [ "$core_fails" -gt 0 ]; then echo "result: fail" >> "$RESULT"
elif [ "$reload_fails" -gt 0 ]; then echo "result: pass, reopen needed" >> "$RESULT"
else echo "result: pass" >> "$RESULT"; fi
cat "$RESULT"
```
