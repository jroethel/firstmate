## 3. Orchestration shape

Waves follow the source plan's dependency graph exactly, plus t15 (added in W1) and t02 (moved to W2 so its worktree carries t15's fix); one manifest per wave, all under `run_name` `firstmate-i1-theming` with `worktrees: true`.
Each wave runs only after the previous gate has committed its patches, because ringer creates every task worktree from the integration branch's committed HEAD.

Three validation layers:

1. Implementer self-check: before finishing, each worker must make the full check `python3 $D/unitcheck.py <key>` (no `--fast`) pass.
2. Per-unit validator: ringer runs `python3 $D/unitcheck.py <key> --fast` as the task's check; exit 0 is the only pass, and the single built-in retry is the repair pass.
3. Orchestrator gate: patches are applied and committed in task-number order, then `python3 $D/unitcheck.py <key> --worktree $R --gate` runs every acceptance step, slow ones included, on the integration branch after commit.

`unitcheck.py` verifies, printing the reason for each failure: custody hashes, that the worktree HEAD did not move, ownership of every changed or untracked path (an empty diff fails a must-change unit), the resume pointer's headings, the verbatim pieces, and the plan's acceptance check; only then does it export `git add -A && git diff --cached --binary` to `$D/patches/<key>.patch`.
`--fast` skips only the acceptance steps marked slow; ownership, the resume pointer, and the verbatim pieces are checked in every mode except `--gate`.

## 4. Hazards and mitigations

Each item is marked where it deviates from the source plan.

  So every manifest check is `unitcheck.py <key> --fast`, which skips the steps below marked slow; the worker must make the full check pass before finishing, and the gate's `--gate` re-run runs every step after commit, so a slow-step failure there sends the unit back.
  A step is slow when it was measured or is expected above about 30 seconds, so no fast step should pass 45 seconds with six workers running.

- Check custody [deviation]: the plan has workers write the proof scripts verbatim, but those scripts are the checks, so `compile.py` extracted them byte for byte to the plan's paths, `custody.sha256` records them with `unitcheck.py` and the verbatim pieces, and every check stops on a hash mismatch; worker specs call them read-only.

- Resume pointers outside the repo [deviation from loop-drive Step 5]: `bin/fm-doc-audience-check.sh` requires every tracked `*.md` to be classified exactly in `docs/documentation-audiences.json` (no globs; an entry for an untracked path also fails), and loop paperwork is excised from the upstream branch, so committed per-unit pointers would break other units' checks.

- Task 1 spec edit [deviation, BATCH, one unit, under 15 lines]: Task 1 classifies six entries, adding this file, `docs/plans/2026-10-05.I1.theming-surface-plan_loop.md`, to the plan's five, all `maintainer-architecture`.

- Task 12 name scan [deviation, BATCH, one unit]: the scan also excludes `docs/reviews`, because the batch-review journal names the themes ("LCARS comment contains `@import`") and Task 12 may not edit it, which made the check unsatisfiable.

- Worker workspace [deviation]: the plan's "work only inside" path and How to run `cd` name the integration checkout, so specs point workers at their own worktree and forbid touching `$R`; workers never `git fetch`, and the orchestrator fetches in pre-flight and before W8.
- Style rules bind human-read artifacts only [deviation]: the resume pointer is machine-read and exempt; tracked Markdown, commit-message-like prose, and script header comments keep one sentence per line and the plain dash.
- Supervisor bleed: every spec opens with the non-Firstmate role and boundary; the repo's SessionStart hook stands down in linked worktrees (`fm_primary_root_matches` requires git-dir equal to common-dir), and the launch unsets `FM_TASK_ID`, `FM_TASK_INBOX`, and `HERDR_ENV` so workers inherit no crewmate identity.
- Disjoint files within a wave: verified for W1 (t01, t03, t13, t15 own disjoint repo paths; t09 and t14 own none) and W2 (t02, t04, t08); a conflict while applying a wave's patches is a scope violation, never resolved by hand.
- Spec size: `compile.py` stops if any spec exceeds 100 KB, below Linux's 128 KiB limit on one argument; the largest is t03 at about 27 KB.
- Gitignored outputs: no unit writes a gitignored repo path, so `git add -A` captures every deliverable; proof outputs land under `/home/jjrdar/_no1/data/firstmate-i1-chain/` by design.
- Shared append-only file: only the orchestrator writes the batch-review journal.
